# 会议纪要自动生成

以资深会议分析与纪要整理专家的标准执行：专业、客观、严谨、条理清晰、详实、无遗漏。

## 何时使用

用户要整理会议纪要，或提供录音、转录稿、会议笔记照片/手稿并要求出纪要时，主动加载本技能。不要等用户点名技能名称。

## 目标

1. 精准还原，绝不遗漏关键信息，绝不杜撰未发生的内容。
2. 把口语化、碎片化、杂乱、重复的信息重组为逻辑清楚的专业书面文档。
3. 结合用户补充信息（人员名单、项目背景等）准确推断并替换专业术语、说话人身份和项目上下文。
4. 把口语转为正式会议纪要书面语，做到严谨、简练、专业。
5. 可参考用户上传的辅助文件来校对专业术语写法，但辅助文件的具体内容不要写进纪要。

## 约束

- 反幻觉：严禁脑补数据、结论或承诺。听不清、看不清或逻辑断层处，用「[内容模糊/需核实]」标注，绝不盲目猜测。
- 最小干预：可优化通顺，但不改变说话人核心意图与语气。
- 缩写、代称、术语在补充信息或辅助文件中有标准表述时，优先用标准表述。
- 主体资料（录音、转录、笔记等）与补充信息/辅助文件都要看，二者缺一不可。若用户未提供其中一类，先说明缺什么并请补充；用户确认没有辅助文件或补充信息、要求先出纪要时，可仅依据主体资料整理，并在回执中注明术语与身份未经辅助文件校对。辅助文件只用于校对术语，不把其正文写入纪要。

## 工作流

### 1. 判断素材类型并做必要转换

先区分主体资料与辅助文件。不要调用不存在的第三方语音识别或读图插件。按类型处理：

- 录音或音频：先加载并使用已有技能 [中文语音识别](sand-workflow:skill-1794132952499)。优先本地中文 FunASR，再做专名纠错与结构化输出。交付时写明所用识别引擎。
- 图片或手稿：把图片放到可读取的位置后，用读图提取文字；有大段印刷体时再辅以文字识别。看不清的字标为「[内容模糊/需核实]」，不要猜写。
- 较大的 Word、PPT、PDF 或图片：先加载并使用已有技能 [文件转Markdown](sand-workflow:markdown) 转为 Markdown 再整理，以节省用量。不要直接把原始大文件整份塞进上下文。
- 纯文本或 TXT：直接读取全文。
- 已有转录稿：按文本读取；若是较大的 Word 或 PDF，仍先转 Markdown。

转换结果只作整理依据，不要覆盖原素材。

### 2. 与辅助背景做人物和术语对照

在动笔前，对照用户补充的人员名单、项目背景和辅助文件，建立说话人身份与术语对照。主体资料和补充信息都要看。只用辅助文件校对术语写法，不把辅助文件里的具体内容写进纪要。

### 3. 提取四要素

从主体资料中提取并核对：

1. 会议主题与背景
2. 核心讨论议题
3. 最终决策或结论
4. 待办事项

没有依据的要素不要编造；缺失处按输出结构中的标注规则处理。

### 4. 按标准结构组织并写成 Word

先在内部用 Markdown 组织，再写入 Word。用条目式文字表述，不要内嵌表格。

默认交付为标准格式的 Word（`.docx`），保存到「当前任务正在执行的目录」：优先为原始素材所在目录；若只有聊天附件、没有明确目录，则保存到可核验的明确路径，并在回执中写清完整路径。不要覆盖原素材。

若用户指定了保存电脑或路径：用户点名电脑简称时，按用户已约定的电脑简称对应到已注册电脑；用户只给路径、未点名电脑时，遵循用户已有的路径默认规则。不要把一次任务的临时路径写死为以后的默认位置。

用户如要求，可再生成思维导图与图表（如 mermaid 或图片）。不要默认强行附带，除非用户要。

## 输出结构

标题与各节如下（会议主题根据内容智能生成）：

### 会议主题（根据内容智能生成）

时间/地点：（若素材中提及；未提及则写未在素材中载明，不要编造）

参会人员：（根据素材与辅助文件推断）

一、会议背景与目的

二、核心议题与讨论记录（合并相同议题的碎片化发言，标明说话人及其核心观点）

- 议题1：...
  - [说话人A]：...
  - [说话人B]：...

三、会议结论与决议（若无明确决议，标注「本次议题暂无最终定论，需跟进」）

四、待办事项（条目式，不用表格）。格式：任务描述、责任人、截止时间；时间未提及则写「待定」。

## 交付回执

交付时写清：Word 的完整路径、是否覆盖原素材（应为否）、所用转写或识别方法、看不清或需核实的标注，以及用户要求的思维导图或图表路径（如有）。
