# 沿用现有PPT风格改稿（流程）

适用：已有一份定稿或半定稿PPT，用户提若干条具体修改。目标是只改要求的页，其余页与原稿完全一致，风格不走样。

## 0. 分工（小智体系）
领导者不亲自动手：梳理要求与交付标准后，派给对应项目/PPT助手执行，验收不达标就打回重做；不要代改。完成时最后一句：「我已确认完成该任务并达到交付标准。」

## 1. 确认底稿与路径
- 先问或查清「以哪一版为底稿」。用户可能刚手工改过，所以以用户电脑上最新那份为准，把它拷到工作区并记下MD5，作为只读底稿。
- 输出另存为新文件，文件名带版本号（如 v4），同目录存放；严禁覆盖原文件和旧版本。
- 文件过大（CopyToBox 上限100MiB）时，在用户电脑上分卷再合并，并核对sha256；仍不行就用已有素材，并向用户说明。

## 2. 先逐条拆解要求，写出完成标准
对每条修改写一行：改哪页、改什么、验收看什么。用户给的页码若与实际不符（比如说是第23页，实际在第22页），先打开核对，改对的页，并在说明中点出。

## 3. 按类型改，各有做法
**A. 名单/人物类（如小同行、专家）**
- 每个人的单位、职务、头衔一律上网查官方页面（学校/院所官网、院士名录），不凭印象。用户给的说法与最新官网不同时，以官网为准，并单独列出差异与来源链接，写入 peers 文件。
- 近期换单位、新当选的头衔要查到。不确定的写「未查到」，不编造。
- 版式：人多时拆成左右两栏，字号不低于14pt。

**B. 观点/AI意见/问答页**
- 先看现有页和专家意见页，避开已经提过的问题，选BP里数据最充分的角度。
- 回答要有论证：结论 + 依据（数据只用BP或本材料已有数字）+ 待量化的点；整体偏积极但不吹。页底加一行来源。
- 说明里写清选这个问题的理由，以及没选的备选题为什么不选。

**C. 精简文字、加配图页**
- 文字压缩约30–40%，保留每页核心结论（Action Title：标题是完整结论句）。
- 行距1.3倍，正文14–16pt，标题栏、底部结论栏保留原样式。
- 每页配一张与论点对应的原图（BP等），保持原比例，只做裁切，去掉原图的标识条与页脚；图注写出处。
- 找不到合适图时，用最接近的实物图，并在说明中如实告知，不用AI整图代替。

## 4. 编辑方式
- 严格走 ppt-master 的 Edit Native 思路（选定页面库映射、原生对象改写），精确改字、换图、微调参考 hands-on-deck：inspect → 按shape id做JSON补丁 → apply --fix --render → 看图 → diff。
- 用原生可编辑的文字框、表格、图表；不用整页图片。
- 沿用原稿的字体、配色、版式；未改动页保持字节级一致。

## 5. 质检门（必过，未过不交付）
1. 渲染所有改动页和整套缩略图，目视检查：溢出、重叠、低对比、文字被图压住（硬伤）、边距、占位符残留。
2. 溢出先改短，再拆页或换版式，最后才缩字。
3. 渲染环境若缺微软雅黑，预览可能与PowerPoint略有差异：对临界处提示用户在PowerPoint里确认；原稿本来就有的问题标明「沿用原稿，未改」。
4. 未改页逐页对比XML、关系文件和图片，确认与底稿一致。
5. 数据与来源：页面上的数字都能追溯到BP、本材料或官网；不新增来源不明的数字。

## 6. 交付
- 新文件复制回用户原路径（先确认能连上用户电脑；清理中转用的临时文件夹，删不掉就如实告知）。
- 同时附一份「修改说明」：底稿与输出、逐页改动、名单及来源、问题选择理由、未改页确认、遗留事项。
- 回复用通俗中文：先说文件放在哪、改了什么，再说与用户要求不一致的地方和需要他确认的点。最后一句加：「我已确认完成该任务并达到交付标准。」
